# v0.3.0 UI 结构与约束

## 一个页面，处理一种主要任务

```text
观测室
  ├─ 投入信息（本机导入表单）
  ├─ 体验一局（显式创建虚构案例）
  └─ 继续一个实验
       └─ 当前牌桌
            ├─ 01 信息：原文、来源；继续到六象
            ├─ 02 六象定位：只显示定位牌阵；点击牌面查看证据
            ├─ 03 洞见探索：只显示五牌；选择与执行分开
            └─ 04 本条手记：只看当前信息的结果
                 └─ 洞见阅读
                      ├─ 正文与替代解释
                      ├─ 支持信号 / 反证条件
                      ├─ 引文核验（默认折叠）
                      ├─ 人类评价
                      └─ 后续证据（新增用表单，原记录不覆盖）

独立区域：洞见手记（本实验搜索/筛选）、牌库、实验记录、设置
```

## 视觉规则

松墨底色、温金高亮、米白主文与低饱和绿色辅助状态。导航、舞台、阅读、元数据采用不同字号和空间节奏。沿用原来的塔罗式卡面，装饰不生成实验事实。首屏的三牌叠影只负责邀请进入观察，不是假装计算完成的结果。

牌桌一次只显示一个阶段，而不是用更小字号塞入所有内容。移动端使用底部导航，五牌排列为三加二，详情支持滚动和明确关闭。读取原文、查看卡牌、重放动画、切换页面均不写入实验。

## 路由

`ui-state.js` 只包含纯函数：URL 解析、阶段可用性、URL 构建与手记筛选。所有模型调用依然在明确的动作处理器内。

- `view=table&stage=map`：定位牌桌。
- `view=table&stage=lenses&lens=migration`：选牌状态。
- `view=reading&note=INSIGHT_ID`：阅读已保存洞见。
- `run` 和 `obs` 绑定上下文；非法的 view/stage 不执行任何命令。
- 尚无定位时不能进入洞见探索；无结果时不展示假结果。
- 操作进行时，浏览器历史不能切换到另一实验/另一信息，从而避免回调写到错误的前端上下文。

## 状态的边界

服务端 run 是实验权威。前端的 view、stage、所选牌、筛选条件和动画是展示状态，不注入提示词，不作为被测系统答案。CLI 写入后通过原有 SSE / 读取同步更新，默认保留人正在看的信息与页面。

设置表单不会因后台每五秒读取而被重置；引文与配置只在需要时展开。浏览器保留的动效偏好不影响引擎。

## 可访问性与测试

使用原生按钮、`dialog`、`details`、搜索框与选择框。弹窗有标题、关闭按钮、Esc 关闭和焦点返回；主要区域可以键盘跳转。动态效果尊重 `prefers-reduced-motion`。这不是全面的 WCAG 合规认证。

实现参考（原始文档）：
- https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog
- https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion

新 UI 用 `tests/ui_smoke.py` 验证；`tests/ui_patch_smoke.py` 是兼容入口，会运行同一个完整套件，不能把两次运行相加宣称为不同测试。
